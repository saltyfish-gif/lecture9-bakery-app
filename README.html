Home Bakery: a small order desk

MGOC50 Lecture 9 · Local classroom simulation · Open the app

Start here / 使用方法

  1. Double-click Start-Bakery.cmd in this folder. Keep its terminal window open.
  2. Open http://127.0.0.1:8000.
  3. Click Get today's messages. Review new orders; valid changes and cancellations are applied automatically.
  4. Book helpers if needed, accept or reject individual requests, then click Accept eligible & end day. Review the forecast and confirm.

中文：双击启动文件，打开上面的地址；先读取当天消息，再审核订单和预约助手，最后结束当天。关闭终端会停止应用，数据仍保存在 bakery.db。

If Python is already on your PATH, you can also run python app.py in this folder. No packages or installs are needed. Stop the server with Ctrl+C. Refreshing or restarting preserves your work.

Plan and implementation

  1. Model orders, incoming requests, helper bookings and the simulation date in SQLite. Import the 13 existing orders once.
  2. Implement notice, capacity, acceptance, changes, cancellations and day advancement as fixed rules, inside database transactions.
  3. Build the wireframe's front page: message controls, financial totals, request review, daily cards, orders and activity history.
  4. Test a copy of the database through all seven message days, capacity boundaries, duplicate imports, helper bookings and persistence. Check the rendered page in the browser.

Files: app.py serves the HTML, CSS, JavaScript and API and owns bakery.db. test_app.py is the regression suite. The seven supplied InstagramOrders HTML files are local input fixtures, not a live Instagram feed. The Workflow Builder is separate and unchanged.

Data model

TableFacts stored once
ordersOrder number, customer, product, quantity, pickup date, lifecycle status.
daysDate and whether its one helper is booked. Capacity and cost are derived.
requestsUnique source message, received day, original text, requested change, decision/reason and linked order.
importsDays already read, preventing repeated imports.
metaCurrent simulation date.
eventsAudit history of decisions, changes and pickups.

One day has many orders; one order may have multiple requests. Hours and prices are calculated from product and quantity, not copied into every row. Daily remaining hours = capacity minus hours of accepted/picked-up orders. Cancelled orders use no capacity.

Rules and state transitions

  • One dozen cupcakes costs $40 and uses 30 minutes. One cake costs $120 and uses 2 hours. One product per order.
  • Each day has 8 hours. One helper adds 4 hours for $100; a second helper cannot be booked.
  • Notice means calendar days: Monday can affect Wednesday or later. Booking, orders, changes and cancellations all require at least two days.
  • New request → Requested → Accepted or Rejected. An incompatible request displays a reason and cannot be accepted; capacity is checked again on each action.
  • Valid changes/cancellations apply automatically when fetched, matching the lecture state diagram. Invalid ones leave the original order unchanged and appear in the review list/history. This refines the wireframe's proposed manual approval step.
  • Changes replace the old quantity, rather than adding the full new quantity on top. Cancellation frees the original hours and removes its value.
  • Batch acceptance processes requests in message order, updating capacity after each decision. Blocked requests are rejected when closing the day. Consider hiring a helper before closing.
  • On closing a day, that day's accepted orders become Picked up at the simulated 5 PM. Days after Sunday have no new messages; continue through Tuesday Dec 1 to complete all pickups.

What the totals mean

Confirmed order value includes accepted and picked-up orders, excluding cancelled orders. Fulfilled sales include only picked-up orders. Helper costs include all booked helpers. Value less helper costs is not profit: ingredients and other costs are not provided. Figures cover the complete classroom horizon, Nov 23-Dec 1.

Deliberate limits

The app understands the supplied structured messages through fixed parsing rules; it does not use AI. Change/cancel messages match a unique accepted order by customer and pickup date. Date-change messages are not present in the supplied files and are not supported by this parser. Ambiguous or unrecognized requests require review rather than guessing. No payments or messages are sent. Decisions and day advancement have no undo; destructive actions show confirmation first. To experiment, launch with a different database path rather than deleting your work.

Testing

Run python test_app.py. Tests copy bakery.db into a temporary directory and restore the copied simulation to its original fixture state; the real database is never modified. The suite checks all message days with and without helpers, sequential capacity, notice failures, cancellation, change deltas, idempotence, preview isolation and restart persistence. A browser test uses a separate temporary copy and port.

Implementation details

Python standard library only: http.server, sqlite3, csv, re, json and datetime. The server binds only to 127.0.0.1. Writes use BEGIN IMMEDIATE transactions and a per-session request token; SQL parameters and escaped page content protect local inputs. All simulation data lives in one SQLite file. No npm, external scripts, fonts, analytics or hosting are used.
